# MVP-чеклист сервиса бронирования аудиторий

Список составлен для первого рабочего запуска внутри организации. Пункты P0 блокируют MVP, P1 нужны сразу после первого запуска, P2 можно планировать после подтверждения спроса.

## P0 — обязательно до запуска

- [ ] Применить все миграции Alembic, включая `0008_booking_archive`, на чистой тестовой и на рабочей базе.
- [ ] Провести сквозную приёмку двух ролей: регистрация и вход, заявка пользователя, модерация, прямая бронь администратора, изменение, отмена, архив и восстановление.
- [ ] Проверить каталог по паспортам: корпус, адрес, аудитория, этаж, вместимость, оснащение, фотографии и схема этажа.
- [ ] Подтвердить правила статусов: какие брони занимают слот, кто и когда может отменять, что считается прошедшим, состоявшим и неявкой.
- [ ] Исключить двойное бронирование параллельными запросами тестом на реальной PostgreSQL.
- [ ] Настроить production-переменные: уникальные пароли БД, длинный `SECRET_KEY`, точный `ALLOWED_ORIGINS`, `COOKIE_SECURE=true`.
- [ ] Запустить сервис только через HTTPS и закрыть прямой внешний доступ к PostgreSQL и backend-порту.
- [ ] Настроить постоянное хранилище для PostgreSQL и загружаемых аватаров; проверить, что данные переживают пересборку контейнеров.
- [ ] Настроить ежедневные резервные копии вне сервера и выполнить пробное восстановление.
- [ ] Создать именные учётные записи администраторов; удалить тестовые учётные записи и заменить временные пароли.
- [ ] Добавить автоматическую проверку backend-тестов и frontend-сборки перед каждым релизом.
- [ ] Подготовить короткую инструкцию администратора и контакт для сообщения об ошибке.

## P1 — первая очередь после запуска

- [ ] Заменить браузерные `prompt/confirm` на брендированные диалоги с валидацией и доступностью с клавиатуры.
- [ ] Разделить `App.jsx`, `AdminBookingCenter.jsx`, `main.py` и `styles.css` на страницы, маршруты, сервисы и тематические стили.
- [ ] Добавить уведомления пользователю о подтверждении, отказе, изменении и отмене брони по email.
- [ ] Добавить восстановление пароля и управляемую деактивацию пользователей.
- [ ] Добавить пагинацию или серверные фильтры для истории бронирований при росте данных.
- [ ] Добавить журнал действий администраторов с фильтрами и экспортом.
- [ ] Настроить централизованные логи, мониторинг ошибок, контроль доступности и предупреждения о сбоях.
- [ ] Добавить тесты API с PostgreSQL и основные e2e-сценарии в браузере.
- [ ] Проверить интерфейс на телефоне, планшете, 1366×768 и при масштабе браузера 125–150%.
- [ ] Провести проверку доступности: подписи полей, фокус, контраст, управление клавиатурой.

## P2 — после стабилизации MVP

- [ ] Повторяющиеся бронирования и массовое изменение серии.
- [ ] Интеграция с корпоративным SSO и календарями.
- [ ] Лист ожидания и автоматическое предложение освободившейся аудитории.
- [ ] Аналитика загрузки корпусов и аудиторий.
- [ ] Выгрузка расписания и отчётов в Excel/PDF.
- [ ] Настраиваемые рабочие часы, праздники и ограничения по корпусам.

## Критерий готовности MVP

MVP готов, когда все пункты P0 закрыты, сквозной сценарий обеих ролей проходит без ручной правки данных в БД, отмены и решения не теряются из истории, двойная бронь не создаётся, а рабочая база восстанавливается из резервной копии.
